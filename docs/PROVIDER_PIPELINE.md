# 모의 공급사·영속 복구 통합

작성: 2026-11-03. `tools/content/provider-pipeline.mjs`. 실제 API 전송·계수·비용 측정은 없다.

## 연결 흐름

1. 내부 요청을 OpenAI 전송 페이로드로 변환한다. 모델·단가·요청과 페이로드의 해시를 고정한다.
2. 주입한 전송기로 입력 토큰 계수 형식의 모의 응답을 받고 requestId.count.json에 저장한다. 계수에는 타임아웃과 중단 신호를 적용한다.
3. 계수값이 상한을 넘으면 예약·생성 없이 차단한다. 허용 범위면 계수값과 출력 상한으로 비용을 예약한다.
4. 어댑터가 응답을 공통 형식으로 변환한다. 영속 실행기가 응답을 저장·정산하고 콘텐츠 구조·개인정보 보조 검사 후 검토 대기로 보낸다.
5. 재개 시 저장된 계수 해시와 입력을 확인하고 저장 응답을 재사용한다. 새 토큰 계수·생성 전송을 하지 않는다.

같은 ID로 입력·모델·단가가 바뀌면 계수 계획 충돌로 거절한다. 작업별 잠금은 계수부터 콘텐츠 검사까지 유지한다. 실제 가격표·토큰 정확성·공급사 사용량 진위는 확인하지 않으며 테스트는 합성 단가와 수치를 사용한다.

모델 거절·불완전 응답은 output=null로 변환하되 확인한 토큰 사용량을 정산한다. 콘텐츠 상태는 structure-rejected가 된다. completed 실행을 콘텐츠 승인으로 해석하지 않는다. 예산 부족은 하위 호출 전에 차단하지만 현재 상위 콘텐츠 상태는 일반 provider-failed로 표시된다. 운영용 오류 분류는 후속 대상이다.

## 검증 결과

준비 4·계산 97·콘텐츠 59, 전체 160개 통과. 신규 통합 테스트 5개:

- 상품 6종의 모의 계수→생성→정산→검토 대기.
- 장부 재개 후 계수·생성 전송 없이 결과 재사용.
- 거절·불완전 응답의 비용 유지 및 구조 거절.
- 입력 토큰 상한·예산 부족 시 생성 미전송.
- 응답 저장 직후 중단을 모의하고 재개 후 정산·검토 대기.

루트에서 `npm run check`로 재현한다. 신규 상태 파일은 테스트 임시 폴더에만 생성하며 120개 평가 대기 기록은 보존했다. 모델 한국어 품질·실제 단가·지연·독립 사주 정확도 평가를 완료한 것은 아니다.

## 남은 조건

실제 전송기는 없고 readiness의 실제 어댑터·토큰 계수는 blocked로 유지한다. 공급사 키·모델·예산 참조도 미설정이다. SDK·HTTP 인증·요청 식별 헤더·청구 조회·안전한 원응답 저장은 후속 구현이다.

저장된 계수 결과는 로컬 신뢰 파일로 취급하며 파일 위조를 막는 서명은 없다. 손상된 계수 파일은 거절하고 자동 삭제하지 않는다. 계수 파일 저장·잠금의 내구성 한계와 합성 데이터 전용 제한은 기존 복구 도구와 같다.

다음은 통합 흐름의 오류를 예산 부족·계수 실패·미확인 과금·응답 검사 실패로 명확히 분류하고, 120개 입력 전체를 대상으로 네트워크 없는 모의 평가 보고서를 만드는 것이다. 이 보고서는 실제 모델 평가와 구분한다.
