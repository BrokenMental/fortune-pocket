# 호출 식별·단가 스냅샷·사용량 대사

작성: 2026-11-03. 모의 제공자 검사, 콘텐츠 전체 41개 테스트 통과. 실제 API·청구 조회 없음.

## 예약과 정산

FileBudget.reserveCall은 callId, requestId, provider, model, priceVersion, rates, inputCap, outputCap을 예약 이벤트에 보존한다. rates는 micro-USD/100만 토큰이며 실제 단가를 실행 전에 확정해 전달해야 한다. 저장된 값의 복사본을 사용해 이후 외부 객체 수정으로 단가가 바뀌지 않는다.

callId는 장부 안에서 고유하다. 같은 요청의 별도 시도는 서로 다른 callId를 사용한다. requestId는 논리 요청 묶음을 식별하며 그 자체로 모든 새 호출을 금지하지 않는다. 식별값에는 본문·이메일·생년월일을 넣지 않는다.

reconcile은 해당 callId·provider·model·responseId·확인한 사용량으로 예약을 정산한다. 저장 당시 단가로 비용을 계산하며 토큰 상한 초과는 장부 중단으로 처리한다. 공급사 응답을 다른 호출에 재사용하거나 같은 호출의 모델·제공자를 바꾸면 거절한다.

같은 호출의 완전히 동일한 대사는 duplicate로 반환하고 이벤트·비용을 추가하지 않는다. 사용량이나 응답 ID가 달라지면 충돌로 거절한다. 동일 응답의 다른 호출 재사용은 제공자별 responseId로 거절한다. 재개 후에도 같은 규칙을 적용한다.

## 실행 제어기 연결

controlledCall의 callMetadata 옵션을 쓰면 시도별 callId에 `:1`, `:2`를 붙여 reserveCall을 사용한다. 제공자에 callId와 requestId를 전달하고 provider/model/responseId/usage가 포함된 모의 결과를 reconcile로 정산한다. 동일한 기본 callId를 재실행하면 제공자 호출 전에 중복 예약으로 차단한다.

기존 메타데이터 없는 경로는 호환을 위해 유지했다. 실제 공급사 연결에서는 추적 경로를 사용해야 한다. 가격·모델 접근·공급사 사용량의 진위를 확인하는 것은 호출자의 책임이며 이 코드는 자체적으로 공급사를 조회하거나 응답 서명을 검증하지 않는다.

파일 장부 재개 시 미정산 예약은 unknown으로 유지한다. 운영자가 공급사 사용량을 확인한 뒤 reconcile을 호출할 수 있으나 실제 조회·대사 명령과 운영 UI는 아직 없다. 보안이 필요한 운영 서버에서는 저수준 settle 직접 호출을 외부에 노출하지 않는다.

## 테스트와 다음 단계

신규 4개 포함 전체 41개 통과: 모델/단가 재개 보존과 중복 대사, 잘못된 식별·사용량 충돌, 응답 재사용·초과 중단, 실행 제어기 연결과 논리 호출 재실행 차단. 기존 계산 코드는 무변경으로 반복하지 않았다.

아직 요청 본문 해시·정확한 전송 페이로드와 요청 ID 결합, 공급사 호출/조회 어댑터, 영속 응답 보존과 실행 재개 전체 흐름은 없다. 실제 모델 호출과 비용 측정은 하지 않았다.

다음은 요청 ID에 정규화한 요청 해시를 연결하고, 모의 제공자의 응답과 실행 상태를 저장해 재시작 시 같은 입력을 중복 전송하지 않는 로컬 복구 흐름을 만드는 것이다. 다중 호스트와 비정상 종료 잠금 복구 등 파일 장부 한계는 유지된다.
