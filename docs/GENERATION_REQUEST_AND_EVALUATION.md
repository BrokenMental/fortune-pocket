# 생성 요청 계약과 평가 기록

작성: 2026-11-03. 실제 공급사 연결·모델 호출 없이 콘텐츠 테스트 15개 통과.

## 요청 계약 1.0

`tools/content/request.mjs`의 buildRequest는 서버 내부 trusted와 사용자 userData를 별도 인자로 받는다. trusted를 외부 API 본문에서 그대로 받아서는 안 된다. 함수 자체는 호출자의 권한·데이터 출처를 증명하지 않는다.

- trusted: 상품, 모드(demo/calculated/journal), 허용 근거 배열, 계산 버전.
- userData: 주제·상황·관계·행사만 허용한다. 이메일·출생 정보·선물 메시지는 허용 필드가 아니다. 허용된 텍스트 안에 섞인 개인정보는 별도 최소화·검토 대상이다.
- calculated 모드는 계산 버전 필수. journal 모드는 회고 상품과 선택 기록 1~7개만 허용한다. 기록 내용이 이용자 데이터라는 성격은 바뀌지 않는다.
- 근거 ID 중복·빈 근거·개별 근거 2,000자 초과를 거절한다. 사용자 필드는 각각 1,000자, 전체 데이터 직렬화는 UTF-8 24,000바이트로 제한한다.
- 지시문과 출력 계약은 고정하고 근거·사용자 텍스트는 data에 둔다. 사용자 텍스트를 시스템 지시문에 이어 붙이지 않는다. 결과의 허용 근거 ID는 trusted에서 생성한다.
- 요청은 공급사 비종속 객체다. SDK의 실제 역할 메시지로 변환하는 어댑터는 아직 없다. 실제 모델이 주입 지시를 따르지 않는지는 별도 평가가 필요하다.
- execution.enabled는 false, 비용 상한과 출력 토큰 상한은 null, 재시도 제한은 1이다. 이 상태로 유료 실행하지 않는다. 공급사 선정 후 서버 예산 승인·토큰 제한·비용 추적·실패 복구를 구현해야 한다.

## 평가 기록

`tools/content/evaluation.json`에는 cases.json과 대응하는 120개 대기 행이 있다. 입력 ID·상품 ID·요청 버전·계산/콘텐츠 버전·모델·결과 경로·검사 항목·검토자·판정 이유·측정값을 기록한다. 아직 결과 파일·모델·비용·지연은 null이다.

recordReview는 결과 경로·콘텐츠 버전·검토자·이유와 구조/근거/개인정보/언어/유용성/반복 검사 결과가 있어야 판정한다. pass에는 모든 검사 true가 필요하다. 파일 존재와 검토자의 신원을 검증하거나 사람의 판단을 자동으로 대신하는 기능은 아니다. 검토 저장은 새 객체를 반환하며 원본 대기 행을 직접 바꾸지 않는다.

측정값 미입력 상태와 문안 검토 통과는 구분한다. 문안 통과가 비용·지연 검증 완료를 뜻하지 않는다. 실제 측정 전 null을 0으로 바꾸지 않는다.

재현: `tools/content`에서 `npm run evaluation` 후 `npm test`. evaluation 명령은 초기 대기 기록을 다시 쓰므로 실제 평가를 시작한 뒤에는 기존 기록을 보존하고 별도 실행 파일로 관리한다.

## 테스트와 다음 작업

신규 5개·전체 15개 통과: 입력 속 지시문의 데이터 유지, 허용 필드·상품·계산 버전·근거 제한, 선택 기록 수, 120개 대기 행 일치, 검토 완료 조건. 이전 계산 97개는 무변경으로 반복하지 않았다.

다음은 실제 모델 없이 샘플 6개로 요청→응답 구조검사→개인정보 신호→검토 대기 기록을 연결하는 로컬 실행기다. 이후 모델·호출 예산을 정하고 공급사 어댑터를 붙여 120개 생성 결과의 품질·반복·원가·지연을 평가한다. 계산 자료의 권리·성인 출생연도 검증은 별도 미완료 항목으로 유지한다.
