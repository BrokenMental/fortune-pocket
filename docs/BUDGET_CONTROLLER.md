# 로컬 예산·실행 제어기

작성: 2026-11-03. `tools/content/budget.mjs`. 유료 호출 없이 모의 제공자로 검사했다.

## 동작

- 금액은 정수 micro-USD로 저장한다. 호출 전 입력 토큰 예상 상한과 출력 토큰 상한, 단가로 최악 비용을 올림 계산해 예약한다. 실제 토큰 계산기는 아직 없으며 호출자가 검증한 수치를 공급해야 한다.
- 확정 사용량이 있으면 비용을 정산한다. 비용과 토큰 상한을 초과하면 제어기를 중단한다. 중복 정산은 거절한다.
- 응답 구조가 거절돼도 사용 비용을 정산하고 최대 1회만 별도 예약으로 재시도한다. 제공자 실패·사용량 누락·타임아웃에는 자동 재시도하지 않는다.
- 사용량 미확인 호출은 unknown으로 예약을 유지하며 다음 예약을 막는다. 공급사 사용량을 별도로 확인한 뒤 settle로 명시적으로 정산해야 한다. 미확인을 0으로 처리하지 않는다.
- 타임아웃은 AbortSignal을 보내지만 실제 공급사의 취소나 미과금을 보장하지 않는다. 늦은 응답으로 예약을 자동 해제하지 않는다.
- 단일 Budget 인스턴스에서 동시 호출은 예약을 동기적으로 반영해 초과 예약을 막는다. 프로세스 재시작·다중 워커·별도 Budget 인스턴스 간 보호는 없다.

## 테스트

`tools/content`에서 `npm test`. 신규 6개 포함 콘텐츠 전체 31개 통과: 예약·정산·중복 정산 거절, 미확인 예약 유지와 명시적 정산, 타임아웃/늦은 응답, 1회 재시도 비용, 상한 초과 중단, 동시 호출 및 기존 runCase 검토 대기 연결.

테스트의 단가·토큰 수는 합성 값이다. 실제 공급사 청구·한국어 토큰 수·비용·지연을 측정한 것은 아니다. 기존 평가 기록의 비용 null도 그대로 유지했다. 실제 제공자 오류 원문은 결과에 넣지 않는다.

## 운영 전 남은 조건

이 제어기는 공급사·인증키·네트워크 호출을 포함하지 않는다. request.execution.enabled=false를 유료 실행 허가로 바꾸는 기능도 없다. 비용 계산과 예약은 구현됐지만 유료 호출 예산 5 USD의 지출 승인을 뜻하지 않는다.

실제 사용 전에는 영속 예산 장부·프로세스 간 원자 예약·실행/호출 ID·중복 응답 방지·재시작 복구·청구 사용량 대사·환율/추가비용 처리와 어댑터가 필요하다. 입력 토큰 상한·청구 출력 토큰·모델 단가를 실제 API 기준으로 연결해야 한다.
