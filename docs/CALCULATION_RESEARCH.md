# 계산 엔진 후보와 검증 계획

조사일: 2026-11-03. 상태: 공식 문서 조사와 [1차 날짜 변환 검증](CALCULATION_VALIDATION.md) 완료. 아래 미실행 표기는 최초 계획 당시 상태이며 최신 실행 범위는 결과 문서를 따른다.

## 후보 비교와 권고

| 후보 | 공식 자료에서 확인한 역할 | 라이선스 표시 | 적용 판단 |
|---|---|---|---|
| [korean_lunar_calendar_js](https://github.com/usingsky/korean_lunar_calendar_js) | 한국 음력과 양력 변환 | MIT | 한국 음력 입력 정규화의 우선 검증 후보 |
| [lunar-typescript](https://github.com/6tail/lunar-typescript) | 중국 음력·절기·간지·팔자 기능 | MIT | 절기·간지 계산의 비교 후보. 한국 시간대 적합성 검증 필요 |
| [한국천문연구원 음양력 변환](https://astro.kasi.re.kr/life/pageView/8) | 양음력 변환, 윤달 구분, 율리우스적일 조회 | 해당 페이지에서 재배포 조건 미확인 | 독립 날짜 대조 자료. 서비스 의존 API로 선정한 것은 아님 |

권고: 한국 음력 정규화와 절기·간지 계산을 어댑터로 분리한다. 두 라이브러리를 조합하는 안을 먼저 검증하되 공급사 확정은 보류한다. 중국 음력 기능이 있다는 이유만으로 한국 음력 입력을 그대로 맡기지 않는다. 한국천문연구원의 달력 간지와 사주의 절기 기준 연주·월주는 용도가 다르므로 같은 값으로 가정하지 않는다.

MIT 표시는 저장소에서 확인했다. 도입할 정확한 버전·커밋과 LICENSE 원문·고지 의무, 포함 데이터의 출처 및 이용 조건은 설치 전 함께 보관한다. 이번 조사에서는 패키지를 설치하거나 버전을 고정하지 않았다.

## 초기 계산 기준안

다음은 구현을 위한 제안이며 검증 후 `calculation_version`으로 고정한다.

- 한국 출생, `Asia/Seoul`의 출생 당시 민간 시각을 입력받는다. 서버 실행 지역과 무관하게 동일한 결과를 반환한다.
- 과거 한국 표준시 변경·서머타임은 별도 검증 대상이다. 검증되지 않은 날짜 구간은 유료 구매 전에 차단하고 고정 UTC+9로 몰래 보정하지 않는다.
- 양력은 그레고리력, 음력은 한국 음력과 명시적 윤달 여부를 사용한다. 윤달 여부 모름은 임의 추정하지 않고 입력 확인을 요구한다.
- 연주는 입춘 순간, 월주는 12절의 경계 순간으로 전환하는 안을 검증한다. 절기 시각의 원본 시간대와 변환 과정을 기록한다.
- 일주는 한국 현지 자정에 바뀌는 안을 사용한다. 23시 전환 유파와 차이가 있음을 결과 안내에 남긴다. 시주 천간도 같은 일주 기준과 일관되는지 확인한다.
- 시지는 자시 23:00~00:59부터 두 시간 단위로 구분한다. 진태양시·경도 보정과 대운은 초기 범위에서 제외한다.
- 출생 시간 모름은 시주를 null로 두고 가상의 정오를 실제 시주로 노출하지 않는다. 입춘·절기 당일처럼 시간에 따라 연주·월주가 달라질 수 있으면 가능한 결과를 비교하고 확정 해석을 제한한다.
- 지원 연도는 두 엔진과 독립 자료가 모두 검증된 교집합으로 정한다. 라이브러리의 지원 범위를 곧바로 제품 지원 범위로 선언하지 않는다.

## 검증 사례 목록

모든 행은 아직 미실행이다. 기대 날짜·간지는 후보 엔진 출력으로 채우지 않고 독립 자료와 선택한 계산 기준으로 확정한다.

| ID | 입력 또는 생성 방법 | 확인 사항 |
|---|---|---|
| C01 | 일반 양력 생일 2000-06-15 12:00 | 기준값 대조, 변환 왕복 |
| C02 | C01의 독립 확인된 대응 음력 | 양·음력 입력의 동일 원국 |
| C03 | 독립 자료에서 확인한 윤달의 첫날·끝날 | 윤달 보존, 다음 달 경계 |
| C04 | 같은 연월일의 평달·윤달 | 서로 다른 양력 날짜로 처리 |
| C05 | 윤달이 없는 해의 윤달 입력 | 명확한 입력 거절 |
| C06 | 음력 작은달 30일 | 잘못된 날짜 거절 |
| C07 | 2000-02-29 / 1900-02-29 | 유효 날짜 / 무효 날짜 |
| C08 | 독립 확인한 입춘 순간 전·동일·후 | 연주·월주 전환 및 경계 포함 규칙 |
| C09 | 12절 각각 경계 전·동일·후 | 월주 전환, 중기와 혼동 없음 |
| C10 | 같은 날 22:59·23:00·23:59·다음 날 00:00 | 일주·시주 기준 일관성 |
| C11 | 12개 시지 경계 각각 전·후 | 누락·중복 없는 시간 구간 |
| C12 | 일반 날짜의 시간 모름 | 시주 없음, 시간 기반 해석 제외 |
| C13 | 입춘·절기 당일 시간 모름 | 불확실한 연주·월주를 확정하지 않음 |
| C14 | 역사적 표준시·서머타임 경계 전·후 | 검증된 변환 또는 지원 거절 |
| C15 | 지원 범위 시작·끝·바깥 하루 | 경계 처리와 구매 차단 |
| C16 | 한국 외 출생, 미래 생일, 형식 오류 | 지원·입력 정책에 맞는 거절 |
| C17 | 서버 시간대를 UTC·서울로 변경 | 동일 입력·버전에 동일 결과 |
| C18 | 프로필 수정·엔진 버전 변경 | 기존 구매 스냅샷과 결과 보존 |

각 사례는 `id`, 입력, 독립 기대값, 출처 URL·조회일, 기준 버전, 엔진 버전, 실제값, 판정, 불일치 원인을 기록한다. 출처가 없는 기대값은 미확정으로 남긴다. 동일 계열 포팅 라이브러리끼리의 일치만으로 독립 검증을 통과시키지 않는다.

## 다음 실행과 통과 기준

1. 정확한 패키지 버전과 데이터 이용 조건을 확인하고 검증 전용 환경을 구성한다.
2. 한국천문연구원에서 C01~C07의 독립 날짜 기준값을 수집하고, 절기 시각 자료를 확보한다. 자동 수집 허용 여부와 자료 이용 조건도 확인한다.
3. 어댑터를 구현해 C01~C18을 실행한다. 역사적 시간대와 절기 시각의 시간대가 확인되기 전에는 한국 시각을 중국 시각으로 단순 치환하지 않는다.
4. 불일치는 원인과 지원 제외 구간을 기록한다. 미해결 경계 오류가 없고 지원 범위를 명시할 수 있을 때 엔진을 선정한다.
5. 이후 상품 6종 샘플 및 상품별 최소 20개 가상 프로필 평가로 연결한다. 실제 생성 비용·지연은 유료 호출 예산을 정한 뒤 측정한다.

이번 완료 범위는 후보 비교·기준안·검증 설계다. 계산 정확도, 패키지 실행 호환성, 독립 기대값 대조는 아직 완료되지 않았다.
