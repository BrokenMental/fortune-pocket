# 요청 해시와 저장 응답 복구

작성: 2026-11-03. `tools/content/recoverable-call.mjs`. 실제 모델 없이 콘텐츠 전체 테스트 46개 통과.

## 흐름

- 요청과 모델/단가 메타데이터를 정규화한 JSON으로 SHA-256 처리한다. 객체 키 순서는 정렬하고 배열 순서는 유지한다. undefined·비유한 수 등 JSON 이외 값은 거절한다.
- requestId별 상태 파일과 배타 잠금을 사용한다. 호출 전 영속 장부에 예약하고 started를 저장한다. 같은 requestId에 입력·모델·단가 등이 달라지면 거절한다.
- 제공자의 응답을 response-saved 상태와 응답 해시로 먼저 저장한다. 다음으로 저장된 호출 식별과 사용량을 장부에 대사하고 completed를 저장한다.
- 응답 저장 뒤 정산 전에 중단되면 재개 시 응답을 다시 전송하지 않고 저장 응답으로 대사한다. 장부 중복 대사는 기존 멱등 규칙을 적용한다.
- completed 상태를 다시 열어도 모델을 호출하지 않고 저장 응답을 반환한다. 원본 요청 본문은 상태 파일에 넣지 않지만 응답 본문은 저장하므로 합성 데이터만 사용한다.
- started에 응답이 없으면 usage-unknown으로 보류하며 자동 재전송하지 않는다. 장부 예약과 상태 저장 사이 중단도 고유 callId로 중복 전송을 막는다.
- 응답 해시 불일치·깨진 JSON·미지원 상태는 거절한다. 해시는 우발적 변경 탐지용이며 공격자가 본문과 해시를 함께 바꾸는 것을 방지하는 서명은 아니다.

상태는 임시 파일에 쓰고 fsync 후 이름을 바꾼다. .tmp 또는 .lock이 남으면 자동 삭제하지 않는다. 기존 로컬 장부와 같이 정상 종료/재개 모의용이며 다중 호스트·전원 장애 내구성·실제 강제 종료 복구를 입증하지 않는다. 부모 디렉터리는 미리 만들고 신뢰한 로컬 경로만 사용한다.

## 검사

`tools/content`에서 `npm test`. 신규 5개 포함 전체 46개 통과: 정규화 해시, 완료 응답의 재개 재사용, 응답 저장 직후 중단 주입과 장부 재개 후 정산, 실패/입력 변경 시 재전송 방지, 저장 응답 변경 거절.

후속 실행에서 제공자가 한 번만 호출됐는지와 동일 비용이 다시 더해지지 않는지를 확인했다. 모의 사용량만 사용했으며 실제 비용·지연 측정은 없다. 계산 코드와 기존 120개 평가 대기 기록은 변경하지 않았다.

## 범위와 다음 단계

recoverableCall은 모의 제공자를 받는 별도 로컬 복구 흐름이다. 앞선 controlledCall의 타임아웃·자동 재시도 루프를 여기로 통합하지 않았다. 제공자가 응답하지 않으면 현재 함수도 기다리므로 실제 공급사에 바로 연결하지 않는다. 재시도는 같은 요청을 임의 재전송하지 말고 확인된 상태에 따라 별도 시도로 설계해야 한다.

completed는 전송·응답 저장·정산 완료라는 뜻이다. 응답의 상품 구조·개인정보·근거 의미 검토 통과나 사용자에게 제공 가능하다는 뜻은 아니다. 공급사 식별/청구 사용량 진위와 외부 상태 조회도 아직 검증하지 않는다.

다음은 이 복구 흐름에 타임아웃과 기존 콘텐츠 검증·검토 대기를 함께 연결하는 것이다. 그 뒤 모델 어댑터·승인된 예산·자료 이용 조건에 맞춰 실제 평가를 준비한다.
