# 로컬 영속 예산 장부

작성: 2026-11-03. 구현: `tools/content/file-budget.mjs`. 실제 API 호출 없이 콘텐츠 전체 테스트 37개 통과.

## 보존과 복구

FileBudget(path, limit)은 Budget과 같은 reserve/settle/unknown/halt/snapshot 인터페이스를 제공한다. 금액 단위는 정수 micro-USD다. 부모 폴더는 호출자가 미리 만들고 신뢰할 로컬 경로만 사용한다.

- init, reserve, settle, unknown, halt를 순서 번호가 있는 JSONL 이벤트로 보존한다. 유효한 다음 상태를 검사한 뒤 이벤트를 쓰고 fsync를 마친 경우에만 메모리 상태를 갱신한다.
- 같은 경로의 .lock 파일을 배타적으로 만들어 장부를 한 프로세스만 연다. 정상 종료 시 close로 핸들과 잠금을 해제한다.
- 재개 시 전체 이벤트를 순서대로 검증·재생한다. 이전 실행의 reserved는 실행/과금 여부를 모르므로 unknown 이벤트를 추가해 복구한다. 미확인 예약은 비용을 유지하며 새로운 예약을 막는다.
- 독립적으로 확인한 사용량으로 settle해야 재개할 수 있다. 중복 정산과 예산 한도 변경은 거절한다. 상한 초과로 중단된 상태도 복구 후 유지한다.
- 줄이 끊겼거나 JSON·순서·이벤트가 잘못된 기록은 열지 않는다. 자동으로 마지막 줄을 삭제하거나 예약을 해제하지 않는다.
- 쓰기·동기화 실패 후에는 해당 인스턴스를 차단한다. 실제 디스크에는 일부 또는 전체 이벤트가 남았을 수 있어 재개 시 다시 검사한다.

controlledCall에 메모리 Budget 대신 FileBudget을 전달할 수 있다. 사용량 정산 뒤 저장 실패가 발생하면 일반 정상 완료로 처리하지 않으며 후속 호출도 차단한다. 저장된 예산 장부에는 사용자 본문을 넣지 않는다.

## 검사

`tools/content`에서 `npm test`. 신규 6개 포함 전체 37개 통과: 미정산 예약 복구·한 번만 정산, 배타 열기·한도 변경 거절, 손상 기록 보존·거절, 중단 상태 보존, 제어기 정상/타임아웃 연결, 저장 동기화 실패 시 제공자 미호출·후속 차단·예약 복구.

테스트는 임시 폴더에서 장부를 닫고 다시 열어 재시작 상태를 모의한다. 실제 프로세스 강제 종료·전원 장애·파일시스템 고장 시험은 아니다. 동기화 실패는 주입한 함수로 모의했다. 이전 계산 테스트는 무변경으로 반복하지 않았다.

## 운영 한계와 잠금 처리

비정상 종료 후 .lock이 남으면 자동 해제하지 않는다. 장부를 가진 프로세스가 없는지 확인하고 원본과 잠금을 백업한 뒤 수동 복구해야 한다. 이번 작업에서는 잠금 삭제 자동화가 없다.

장부는 로컬 단일 파일용이다. 네트워크 파일시스템·다중 호스트·심볼릭 링크 공격·디스크 변조·장부 파일 자체 삭제에 대한 보장은 없다. 파일 fsync가 모든 저장장치의 전원 장애 내구성을 보장하지 않으며 디렉터리 fsync도 구현하지 않았다. 암호학적 감사 서명이나 트랜잭션 DB를 대체하지 않는다.

외부 호출 ID·예약별 모델/단가 스냅샷·사용량 조회와 대사·전체 실행 복구는 다음 과제다. 동일 요청 중복 호출을 서버 차원에서 방지하는 기능도 아직 없다. 공급사 연결·예산 승인이 준비되기 전 유료 호출하지 않는다.
