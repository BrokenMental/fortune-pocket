# 복구·타임아웃·콘텐츠 검사 통합

작성·실행: 2026-11-03. 콘텐츠 전체 테스트 50개 통과. 실제 API 호출 없음.

recoverable-call에 1~60,000ms의 타임아웃과 AbortSignal을 연결했다. 시간 초과나 제공자 실패 시 예약을 unknown으로 유지한다. 늦은 응답은 저장·정산에 사용하지 않으며 재개해도 자동 전송하지 않는다. 취소 신호가 실제 공급사 취소·미과금을 보장하지는 않는다.

recoverable-content는 기존 요청 생성→영속 예약→응답 저장→정산→구조 검사→개인정보 보조 검사→검토 대기를 연결한다. 재개 시 저장 응답에도 콘텐츠 검사를 다시 적용한다. completed는 실행/정산 상태이며 pending-review는 별도 콘텐츠 상태다. 문안 자동 승인으로 처리하지 않는다.

구조·개인정보 문제로 응답을 거절해도 확인한 호출 비용은 유지한다. 개인정보 신호가 나온 응답은 상위 반환 출력에서 제외한다. 단, 하위 복구 저장소에는 원응답이 있으므로 현재 도구는 합성 데이터 전용이다. 실제 개인정보 저장용으로 사용하려면 암호화·권한·보존기간·삭제 및 격리 정책이 필요하다.

## 검사와 실행 결과

신규 4개 포함 전체 50개 통과: 완료/재개 후 검토 대기, 구조/개인정보 거절 시 비용 유지, 타임아웃·늦은 응답·재개 무전송, 잘못된 요청의 예약/호출 미실행. 기존 계산 검사는 무변경으로 반복하지 않았다.

`tools/content`에서 `node run-recoverable-demo.mjs`로 6종 통합 실행과 저장 응답 재사용도 확인했다. 출력 폴더는 `runs/a119e1fa-8af1-4d7a-bd56-149b4dd03af7/`이며 integrated-report.json과 상태 파일·장부를 보존했다. 여섯 상품 모두 pending-review, 재사용도 같은 상태다. 모의 장부 비용은 합성 수치이며 실제 비용과 지연 실측이 아니다. 기존 120건 평가 기록은 유지했다.

## 남은 조건

자동 재시도는 이 복구 흐름에서 하지 않는다. 상태 파일은 잠금·로컬 파일의 기존 한계를 따른다. 검토 결과/출력 파일의 운영 저장소 연결, 실제 제공자 사용량 진위 확인·청구 조회, 실제 토큰 계산, 모델별 전송 스키마는 남아 있다.

다음은 현재 도구들을 반복 실행할 공통 검증 명령과 준비 상태 보고서를 만들고, 실제 API 연결 전 필요한 설정·예산·입력 준비 여부를 읽기 전용으로 검사하는 것이다. 유료 호출은 별도 승인 범위와 접근 수단이 마련된 뒤 진행한다.
