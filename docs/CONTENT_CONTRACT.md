# 콘텐츠 출력 계약과 평가 입력

작성: 2026-11-03. 구현: `tools/content/content.mjs`. 공급사·프레임워크 의존성이 없는 검증 전용 코드다.

최신 후속: [샘플 JSON·오류 사례 검증](CONTENT_SAMPLE_VALIDATION.md), 콘텐츠 테스트 총 10개 통과. 공유 함수에 개인정보 보조 탐지·차단을 추가했지만 아래의 의미·개인정보 검토 한계는 남아 있다. 아래 테스트 5개 기록은 초기 이력이다.

## 출력 스키마 1.0

```json
{
  "schemaVersion": "1.0",
  "productId": "MATCH_MINI",
  "title": "가상 결과 제목",
  "cards": [
    { "id": "C1", "heading": "카드 제목", "body": "카드 본문", "evidenceIds": ["F1"] }
  ],
  "questions": ["함께 답할 질문"],
  "limitations": "해석 범위와 불확실성 안내"
}
```

위 JSON은 필드 설명 예시다. 실제 MATCH_MINI는 카드 3장·질문 2개가 필요하다. 알 수 없는 필드는 루트·카드 모두 거절한다. 카드 ID는 중복할 수 없다.

| 상품 | cards | questions |
|---|---:|---:|
| MATCH_MINI | 3 | 2 |
| MATCH_FULL | 6 | 5 |
| GIFT_MINI | 1 | 0 |
| GIFT_BOOK | 4페이지 | 0 |
| JOURNAL_PROMPT | 짧은 해석 1 | 5 |
| JOURNAL_REVIEW | 주제·질문 안내·행동 3 | 별도 질문 1 |

회고 질문은 두 번째 카드의 안내와 별도 질문 필드로 표현한다. 기존 문안 샘플을 이 계약으로 변환할 때 카드 안 질문 중 하나를 별도 필드로 옮긴다. 이 분량은 계약 초안이며 상품 버전 확정 전 조정할 수 있다.

문자 수는 코드 포인트 기준으로 제목·카드 제목 60, 본문 600, 질문 160, 한계 안내 400자 상한을 둔다. 빈 문자열과 `<`, `>`를 거절한다. 이는 출력 형식 제한이며 HTML 보안의 전체 구현을 대신하지 않는다. 실제 화면은 텍스트로 렌더링해야 한다.

근거 ID는 서버가 고정한 `allowedEvidenceIds`에 속해야 한다. 회고는 사용자가 선택한 1~7개 기록만 컨텍스트로 전달한다. 검증기는 ID 소속을 검사하며 문장이 그 근거를 실제로 뒷받침하는지는 별도 의미 검수가 필요하다. 모델이 컨텍스트를 만들거나 허용 ID를 추가하게 하지 않는다.

직접 쓴 선물 메시지·별칭·템플릿·가격·원본 프로필은 모델 출력에 넣지 않는다. 앱이 별도 데이터로 관리하고 구매자가 확인한 공개 범위에만 삽입한다. 메시지는 별도 입력 검증과 텍스트 렌더링이 필요하다.

## 공유용 필드

최신 수정: JOURNAL_REVIEW의 publicCards 직접 공유는 차단한다. [별칭·공개 문안 수정](EDITORIAL_REVISION.md)의 별도 일반 질문 문안만 확인 후 선택할 수 있다. 아래 일반 카드 투영 설명은 회고를 제외한 상품에 적용한다.

`publicCards`는 검증을 통과한 결과에서 선택 카드만 반환하고 근거 ID를 제거한다. 빈 선택·없는 ID·중복 선택은 거절한다. 제목·한계 안내와 선택 카드의 ID·제목·본문만 반환한다.

본문에 자연어로 섞인 출생 정보·일기 원문까지 제거하는 기능은 없다. 개인정보 검토와 소유권 검사, 공유 동의·만료·철회·접근 제어를 통과한 뒤 사용해야 한다. 현재 함수 자체를 공개 API로 연결하지 않는다.

## 가상 입력 120개

`tools/content/cases.json`에 상품별 20개씩 총 120개를 저장했다. `fixtures.mjs`가 20개 구체 상황을 6종 상품에 배정한다. 서로 독립된 120개 인물 이야기를 제작한 것은 아니다.

- 성인 연령대·주제·구체 상황·시간 모름을 포함한다.
- 궁합은 친구/연인, 선물은 행사·메시지, 회고는 1·3·7개 가상 기록을 포함한다.
- 실제 생년월일·원국은 없으며 `calculationStatus`는 `not-computed`다. 계산된 개인화 사실을 제공하지 못하는 현재 상태에서는 실제 사주 해석용 입력으로 쓰지 않는다.
- 모든 항목은 생성 대기 상태이며 비용·지연은 null이다. 120개 결과 생성·평가 완료로 집계하지 않는다.
- 지시문 주입·기록 0개·개인정보 누출 등 실패 시나리오의 전수 입력 묶음은 후속 대상이다.

## 재현과 검증 결과

`tools/content`에서 `npm run fixtures`로 JSON을 재생성하고 `npm test`로 검사한다. 추가 패키지 설치는 필요 없다.

테스트 5개 통과: 상품 6종의 정상 구조, 잘린 분량·다른 상품·태그·초과 필드·허용되지 않은 근거 거절, 회고 기록 수 제한, 공유 필드 투영, 상품별 입력 20개·총 120개와 미측정 상태 확인. 계산 코드 변경은 없으므로 기존 계산 테스트는 반복 실행하지 않았다.

다음 작업은 문안 샘플 6종을 이 계약의 JSON으로 옮겨 검사하고, 입력 주입·근거 모순·개인정보 누출의 실패 사례 및 의미 검토 절차를 추가하는 것이다. 실제 모델 생성과 원가 측정은 그 다음 단계다.
