# 샘플 JSON과 오류 사례 검증

작성: 2026-11-03. 콘텐츠 테스트 10개 통과. 계산 코드는 변경하지 않아 기존 계산 97개는 반복 실행하지 않았다.

`tools/content/samples.json`에 기존 문안 6종을 구조화했다. `samples.mjs`가 `PRODUCT_SAMPLES.md`에서 카드·질문·읽는 기준을 읽고 계약을 검사한다. 회고 첫 질문은 questions로, 본문 근거 표시는 evidenceIds로 옮겼다. 선물 메시지는 출력과 별도 필드다.

각 샘플은 demoOnly이며 계산하지 않았다. DEMO_SCENARIO는 가상 설정이고 실제 계산 근거가 아니다. 120개 평가 결과가 아닌 기존 편집 샘플 6개다.

재현: `tools/content`에서 `npm run samples` 후 `npm test`. 저장 JSON과 원문 변환 결과 일치도 검사한다.

## 검사 결과와 한계

- 상품별 계약·분량·공유 필드 검사 통과. 선택하지 않은 일기 ID를 근거로 쓰면 거절한다.
- 이메일·한국 휴대전화 형태, 등록된 비공개 문구, 일부 지시문 재노출을 탐지하는 보조 검사를 추가했다. 공유 함수는 선택 공유본에서 신호가 나오면 반환을 차단한다.
- 서버는 원문·출생 정보 등 민감한 값을 context.privateTexts에 등록해야 한다. 공백·전각 문자 일부 변형을 정규화해 비교한다. 해당 컨텍스트를 모델 출력에서 받지 않는다.
- 바꿔 쓴 생년월일·일기 요약·다른 연락처 형식·우회 지시문은 놓칠 수 있다. 개인정보 완전 탐지 또는 실제 모델의 주입 방어 완료가 아니다.
- 허용된 근거 ID를 붙이고 J1의 의미를 반대로 바꾼 문장은 구조 검사에 통과한다. 이 한계를 테스트로 명시했으며 의미 검토에서 거절해야 한다.

## 의미 검토 절차

1. 카드의 근거 ID뿐 아니라 실제 원문·계산 사실과 본문의 의미를 대조한다. 선택 기록 밖 사건·심리·성격 단정은 거절한다.
2. 제목·한계 안내·선택 카드에서 출생 정보·일기 원문·재식별 가능한 세부 내용을 검토한다. 비공개 문구 비교는 검토 보조다.
3. 사용자 입력은 명령이 아닌 데이터로 전달한다. 실제 모델 호출이 없어 모델의 지침 준수는 아직 미검증이다.
4. 검토자·버전·근거·판정·수정 사유를 기록한다. 근거 모순·개인정보가 남으면 제공·공유를 보류한다. 재생성은 예산·재시도 제한을 따른다.

현재 공유 함수에는 인증·소유권·동의·만료 처리가 없어 실제 공개 API에 바로 연결하지 않는다. 다음은 신뢰 컨텍스트와 사용자 데이터를 구분한 생성 요청 계약 및 평가 기록 틀 작성이다. 실제 모델·예산 확정 후 120개 결과를 평가한다.
